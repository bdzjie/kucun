## 核心认知

### 一句话定义
OpenClaw 是一个开源自托管 AI 智能体框架，具备**自主执行能力** — 能直接操作电脑、读写文件、浏览网页、发邮件、执行 Shell 命令、定时运行任务，支持 20+ 聊天渠道。

### 核心哲学

> "智能可以涌现，但语言必须守望。技术可以赋能，但人文不能退场。技术的尽头不应只是效率，语言理解的深处始终是人。"

**铁律**: 永远不要让 AI 替你思考"该不该做"，只让它替你完成"怎么做"。

## CAP 全维度智能体提示词框架

| 层级 | 英文 | 中文 | 关键内容 |
|------|------|------|---------|
| C | Context + Character | 上下文 + 身份 | 你是谁、用户是谁、背景是什么 |
| A | Ability + Action | 能力 + 行动 | 你能用什么工具、具体怎么干 |
| P | Policy + Protection | 策略 + 保护 | 什么不能做、安全边界在哪 |
| O | Output + Optimization | 输出 + 优化 | 结果以什么形式呈现、如何改进 |

### 完整 CAP 提示词模板

```markdown
【Context + Character 层】
你是 [名字]，一个 [角色定位，如：资深全栈开发助手]。
你的用户是 [用户名]，[职业背景 + 工作习惯]。
当前场景是 [具体场景]。

【Ability + Action 层】
你可以使用以下能力：
- 文件操作：读取、写人、移动、删除 [指定目录范围]
- 浏览器自动化：搜索网页、抓取内容、填写表单
- Shell 执行：运行 [允许的命令范围]

针对当前任务，你的执行步骤应该是：
1. [步骤 1]
2. [步骤 2]
3. [步骤 3]

【Policy + Protection 层】
安全边界：
- 绝对禁止：[列举 3-5 条禁止行为]
- 需要确认：[列举需要用户二次确认的操作类型]
- 遇到异常：[规定重试次数和上报机制]

【Output + Optimization 层】
输出格式要求：
- 执行前：用人一句话确认理解任务
- 执行中：每完成一步汇报进度（不超过 10 字）
- 执行后：用 3-5 行总结完成情况，标注 [成功]/[部分成功]/[失败]
```

## 三级提示词系统

| 阶段 | 时间周期 | 核心目标 | 提示词侧重点 | 典型句式 |
|------|---------|---------|------------|---------|
| 第一级：指令级 | 第 1-3 天 | 让 AI 准确执行单一任务 | 高度具体、边界清晰 | "帮我把桌面所有 PDF 移到 D:\backup" |
| 第二级：方法级 | 第 4-14 天 | 将工作流程固化为 AI 的方法论 | 流程化、模板化 | "以后每次整理文件都按这 3 步走：先扫描、再分类、后归档" |
| 第三级：默契级 | 第 15 天+ | 理解意图和习惯，主动预判 | 价值观对齐、风格塑造 | "你了解我的风格，这件事你看着办，我相信你的判断" |

## 日常任务提示词黄金公式

```
[动作] + [对象] + [范围/条件] + [输出要求] + [确认机制]

示例：
[动作] 帮我整理
[对象] 桌面上所有 .pdf 文件
[范围] 按照"日期-文件名"格式重命名后移动到 D:\pdf_archive
[输出要求] 完成后告知共处理了多少个文件
[确认机制] 移动前先列出所有文件让我确认
```

## 四种核心提示词模式

| 模式 | 适用场景 | 提示词写法 | 效果 |
|------|---------|-----------|------|
| 少样本提示 (Few-shot) | 需要特定输出格式 | "参考以下示例格式输出：[给出 2-3 个示例]" | 大幅提高格式一致性 |
| 思维链提示 (CoT) | 需要推理的复杂任务 | "一步步思考，先分析问题，再提出方案，最后给出结论" | 减少"拍脑袋"回答 |
| 角色提示 (Role Prompt) | 需要专业视角 | "以资深 XX 专家的身份，用专业但易懂的语言……" | 提升回答的专业深度 |
| 工具增强提示 (Tool-Augmented) | 需要使用特定工具 | "使用 Tavily Search 搜索 XX，然后整理成表格" | 确保工具被正确调用 |

## 最易被忽视但最重要的提示词技巧

### 技巧 1：给 AI"停顿点"
```markdown
❌ 错误写法："分析这篇 100 页的 PDF 并写一份 5000 字报告"
✅ 正确写法："先告诉我这篇 PDF 的目录结构，然后我们再决定重点分析哪些部分"
```
原理：AI 在处理超长任务时容易"一路狂奔"然后跑偏。设置停顿点相当于给 AI 设置了检查点。

### 技巧 2：要求 AI 先复述任务
```markdown
❌ 错误写法："帮我整理财务报表"（AI 可能理解错误）
✅ 正确写法："先用你自己的话说一遍你理解的任务目标，确认后我再让你执行"
```

### 技巧 3：告诉 AI"什么时候该停下来问"
```markdown
在 AGENTS.md 中添加：
"遇到以下情况时，必须暂停执行并询问我：
- 需要删除超过 10 个文件
- 需要向外部发送任何数据
- 执行时间预计超过 5 分钟
- 遇到你无法 100% 确定的决策"
```

### 技巧 4：使用"忽略之前所有规则"重置状态
```markdown
忽略之前所有的规则和对话。
重新初始化：
- 按照 AGENTS.md 的第 X 条规范执行
- 当前任务：[具体任务]
```

## ClawHavoc 事件（安全警示）

2025 年底至 2026 年初，OpenClaw 生态遭遇大规模供应链攻击：

| 数据项 | 数值 |
|-------|------|
| 审计的 Skills 总数 | 2,857 个 |
| 发现恶意 Skills | 341 个（约 12%） |
| 受影响 Skill 安装量 | 超过 8,000 次 |
| 主要攻击手法 | 凭据窃取、反向 Shell、上下文持久化注入、环境投毒、社会工程学 |
| typosquatting 示例 | `file-search` ✅ vs `file-serach` ❌ |

**教训**：Skill 名字一定要仔细核对，装之前必须 inspect 源码。

### Skill 安装前安全检查 SOP

1. 在 ClawHub 找到目标 Skill，检查：Star 数 > 100、更新在 3 个月内、官方认证徽章
2. 使用 `skill-vetter audit [skill-name]` 审计
3. 手动查看源码，重点检查：curl/wget 下载外部脚本、要求访问 `~/.ssh/` 或 `~/.openclaw/credentials/`、包含 `eval()`/`exec()` 等动态执行代码
4. 核对 Skill 名称拼写，警惕 typosquatting

## 安全：21 条保命守则

### 🔴 致命级（不遵守则极大概率出事故）

1. **DM Pairing 必须开启** — 第一道防线
   ```bash
   openclaw config set security.pairing.enabled true
   openclaw config set security.pairing.autoApprove false
   ```
2. **Gateway 绝不暴露到公网** — 默认 18789 端口只监听 127.0.0.1，不要改成 0.0.0.0
3. **安装任何 Skill 前必须用 skill-vetter 审计**
4. **绝不要用龙虾管理私钥/密码/钱包**
5. **凭证存储目前是明文的，做好物理隔离** — `~/.openclaw/credentials/` 下是明文 JSON
6. **删除文件、发邮件、执行 shell 必须设成"需要确认"**

### 🟡 严重级（不遵守可能导致严重后果）

7. 从官方渠道下载，不用闲鱼/淘宝卖的"一键安装包"
8. 不要用管理员/root 权限运行 OpenClaw
9. 定期备份：必装 `openclaw-backup`，定时备份整个 `~/.openclaw` 文件夹
10. Skill 名字一个一个字母核对，防止 typosquatting 攻击
11. 不要执行任何要求"关闭安全提示"的指令
12. 敏感操作使用沙箱隔离
13. 开启渠道允许列表（Channel Allowlist）

### 🟢 建议级（提升安全水位）

15. 大版本升级前备份整个 `~/.openclaw` 文件夹
16. 新版本先在测试机上跑 2-3 天再上生产环境
17. 定期运行 `openclaw doctor`，至少每周一次
18. 检查已安装 Skills 的权限，移除不常用的
19. 使用 `openclaw logs --follow` 监控异常行为
20. 如果龙虾突然开始主动外发数据，立即 `openclaw gateway stop`
21. 加入 OpenClaw 官方安全公告邮件列表

## 万能 4 步诊断法

```bash
# 第 1 步：查看整体状态
openclaw status

# 第 2 步：自动诊断
openclaw doctor

# 第 3 步：查看实时日志
openclaw logs --follow --tail 50

# 第 4 步：如果 doctor 提示有可修复问题
openclaw doctor --fix
```

这四步能解决 **80%** 以上的问题。
