### 3种检索策略 (RAG)

#### 1. Explainable GraphRAG (旗舰)
**知识提取流程**:
```
文档 → 分块 → LLM实体抽取 → 知识子图 → 图存储 + 向量存储
```

**检索流程**:
```
用户问题
  ↓ (LLM概念抽取)
概念Embedding
  ↓ (向量相似度)
实体检索 → 子图遍历(深度N) → 语义预过滤
  ↓ (LLM边评分)
相关边选择 + 推理解释 → 来源追溯 → LLM生成答案
  ↓
完整审计链 ( provenance triples )
```

**关键创新**:
- LLM概念抽取 (不只是原始query embedding)
- 子图遍历 + 边评分 (关系感知)
- 完整来源追溯 (可解释性)
- 并行 edge scoring + reasoning

#### 2. OntologyRAG
**核心思想**: 用领域本体指导知识抽取
```
 ontology subgraph → 引导 → 一致性知识图谱
```

问题: 完整ontology放入context window太大会撑爆
解决方案: 用GraphRAG算法本身从存储的ontology图中检索相关子集

**适合**: 专业领域（医学/法律/金融），有明确本体定义

#### 3. Explainable Document RAG
传统方法: chunk embedding → cosine similarity → 直接返回

TrustGraph改进:
- 概念抽取 grounding
- provenance triples 审计链
- **局限**: 无关系感知、context碎片化、多跳推理差

### Context Cores (知识核心)

**定义**: 可移植的版本化知识包
```
Context Core 结构:
├── Ontology Schema (本体schema)
├── Context Graph (实体 + 关系 + 证据)
├── Graph Embeddings (向量索引)
├── Source Manifest (来源/出处/时间)
└── Retrieval Policies (检索策略)
```

**3种状态**:
- Offline: core文件状态
- Online: 加载到knowledge-management store
- Loaded: 加载到retrieval stores，可查询

**用途**:
- 跨项目/环境迁移
- 隔离不同领域知识 (医疗/法律分开)
- 运行时动态加载/卸载
- 1%创建时间即可reload (快速切换上下文)

---

### 知识图谱 vs 上下文图谱

| | 知识图谱 | 上下文图谱 |
|--|---------|-----------|
| 内容 | 实体 + 关系 | 实体 + 关系 + **来源** + **推理过程** |
| 可问 | "知道什么" | "怎么知道的" + "为什么相信" |
| 解释性 | 无 | 有 (provenance as graph data) |

## 22:02 GitHub Research — Kronos 金融基础模型

### Kronos — 金融市场语言模型
Repo: `NeoQuasar/Kronos` ⭐ ~19.5K | MIT | Python/PyTorch
**定位**: 第一个专门针对金融K线序列（K-lines）的开放源码基础模型

### 核心技术路径
```
OHLCV K线数据 (5维连续值)
        ↓
[第一阶段] KronosTokenizer
  - 将连续OHLCV量化为层级离散token
  - 多维→单维离散化，类似NLP的BPE
        ↓
离散token序列 (512/2048长度)
        ↓
[第二阶段] Autoregressive Transformer
  - GPT式自回归预测下一个token
  - 学会K线的"语言规律"
        ↓
输出: 未来K线 (open/high/low/close/volume)
```

### 模型系列
| 模型 | 参数量 | 上下文 |
|------|--------|--------|
| Kronos-mini | 4.1M | 2048 |
| Kronos-small | 24.7M | 512 |
| Kronos-base | 102.3M | 512 |
| Kronos-large | 499.2M | 512 |

### 三个应用场景
1. **短期价格预测** — 输入历史K线 → 输出未来N根K线（T=温度采样, top_p=nucleus采样）
2. **回测 (Backtesting)** — `run_backtest_kronos.py`，历史模拟交易 + 夏普比率
3. **微调 (Fine-tuning)** — 两阶段：先Tokenizer适配数据分布，再训预测模型

### 关键参数
| 参数 | 含义 |
|------|------|
| lookback | 历史K线条数（如400根5分钟K线）|
| pred_len | 预测K线条数（如120根=未来10小时）|
| T (temperature) | 采样温度，高=随机多 |
| top_p | nucleus采样概率 |
| sample_count | 采样路径数，多条路径取平均更稳定 |

### 对 OpenClaw 的启发
| Kronos 思想 | OpenClaw 应用 |
|------------|--------------|
| 领域特定Tokenizer | 代码结构专用tokenizer（函数/变量/控制流分段）|
| 两阶段预训练 | 先训代码tokenizer → 再训Agent模型 |
| 统一多任务模型 | 同一模型处理 debug/重构/解释/生成 |
| 层级离散化 | 记忆层级压缩（Core→Active→Warm→Cold→Archive）|

## 22:07 GitHub Research — Ontology 方向

### 三个不同方向的 Ontology

#### 1. TrustGraph (⭐ 1,994) — Context Graph Platform
- 已详细分析（见上方21:10条目）
- 核心：OntologyRAG + GraphRAG + Context Cores

#### 2. Ontology 区块链 (ontio/ontology)
- Go语言实现的公链基础设施
- 非本文重点

#### 3. 知识图谱本体论 (Knowledge Graph Ontology)
在AI领域，Ontology Engineering = 定义概念+关系+约束，让AI能精确推理

**核心概念**:
| 概念 | 说明 |
|------|------|
| Entity | 实体（人/物/概念） |
| Relationship | 关系（is-a, part-of, works-for）|
| Property | 属性（name, age, date）|
| Class | 类（概念的集合）|
| Inference | 本体推理（基于规则导出新知识）|

**技术栈**: OWL / RDF / SPARQL

### TrustGraph vs OpenClaw 对比
| TrustGraph | OpenClaw |
|-----------|----------|
| Context Core (Ontology+Graph+Embeddings+Provenance+Policies) | Ebbinghaus Memory + Entity注册表 |
| GraphRAG (子图遍历+边评分) | BM25 搜索 |
| Pulsar 事件流 | Session事件 |
| 来源追溯作为一等公民 | 记忆无来源标注 |
| Modular 包设计 | 单一仓库 |

### 下一步借鉴方向
1. **Context Core 模式** → 把 EbbinghausMemory + Entity注册表 + 来源标注 打包成可迁移单元
2. **GraphRAG 检索** → 升级 BM25 为 概念抽取→实体检索→子图遍历→LLM评分
3. **来源追溯** → 每条记忆标注来源（用户输入/文件读取/推理得出）
4. **Pulsar 事件流** → Session事件异步触发记忆抽取，不阻塞主流程

### 22:17 已落地 — TrustGraph 功能引入 OpenClaw

**新增4个模块** (commit 1875eec):

#### 1. `modules/knowledge/memory_provenance.mjs`
来源追溯系统
- 6种SourceType: user_input/file_read/tool_result/inferred/llm_generated/session_replay
- 4级Confidence: HIGH(0.9)/MEDIUM(0.7)/LOW(0.4)/SPECULATIVE(0.2)
- 6种Pathway: direct/extracted/pattern_matched/aggregated/llm_synthesized/inferred
- ProvenanceStore: entity索引 + provenance日志 + chain查询
- `attachToMemory()`: 将来源标注附加到记忆条目

#### 2. `modules/knowledge/memory_graph.mjs`
轻量级知识图谱（无需Neo4j/Cassandra）
- Triple: subject --[predicate]--> object
- 16种Predicate: is_a/part_of/depends_on/knows/contradicts/supports...
- Entity: name/type/aliases/description/tags
- KnowledgeGraph: traverse(深度N)/findHubs/findClusters/findConnection
- extractFromText(): 6种关系模式自动抽取
- toMermaid(): 可视化导出

#### 3. `modules/knowledge/memory_rag.mjs`
TrustGraph GraphRAG风格的检索
- extractConcepts(): 从query提取概念（模式匹配）
- retrieve(): 概念→实体→子图遍历→评分排序
- answer(): 合成问题答案 + 来源追溯
- ingest(): 内容→实体→三元组→可检索
- RetrievalResult: content/score/source/concepts/relationships/explanation

#### 4. `modules/knowledge/context_core.mjs`
可移植版本化知识包
- ContextCore = ontology + entities + triples + memories + policies + provenance
- 5种Domain: persona/project/skill/memory/all
- export()/load(): .core.json文件格式
- merge(): 合并多个core
- CoreDomain枚举 + listCores()列出可用core

**数据流**:
```
memory_provenance: 每条记忆附加来源标注
     ↓
memory_graph: 实体关系抽取 → Triple Store
     ↓
memory_rag: 概念检索 → 子图遍历 → 关系感知答案
     ↓
context_core: 打包 → 便携可分享的知识单元
```
